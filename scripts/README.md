# scripts/ — как этим пользоваться

Пять скриптов плюс два питоновских помощника. `emulator.sh`, `install-phone.sh` и
`screenshots.sh` — про то, чтобы собранное куда-то поставить и показать, остальные — про
то, чтобы задача из `todo/` доехала до `develop` сама.

| файл | что делает |
| --- | --- |
| `grind.sh` | цикл по бэклогу: выбрать задачу → сделать → ревью → закрыть → следующая |
| `close-task.sh` | закрыть одну задачу: PR, авто-мёрж, перенос файлов в `todo/done/` |
| `claude-stream.py` | делает вывод неинтерактивной сессии читаемым (мысли, вызовы инструментов) |
| `emulator.sh` | локальный AVD `dosmotr_ci_35` для инструментальных тестов |
| `install-phone.sh` | собрать ветку и поставить APK на телефон по USB |
| `screenshots.sh` | снимает шесть кадров для карточки магазина и иконку 512×512 |
| `store-graphics.py` | подписи поверх кадров и feature graphic 1024×500 |

```bash
scripts/install-phone.sh                      # debug с develop
scripts/install-phone.sh feature/foo          # с этой ветки
scripts/install-phone.sh --production         # подписанный release вместо debug
scripts/install-phone.sh --store              # флейвор store (без блока донатов)
```

`install-phone.sh` пинит `ANDROID_SERIAL` на **физическое** устройство: install-задача
ставит APK на все подключённые разом, так что с поднятым эмулятором сборка уезжает и
туда. Ветку переключает только на чистом дереве (без stash — потерянный stash дороже),
подтягивает `--ff-only` и по выходу возвращает ту, на которой были, чем бы сборка ни
кончилась. `--production` перед запуском Gradle проверяет `release.*` в
`local.properties` и наличие keystore: иначе release собрался бы неподписанным и adb
отказал бы уже после R8.

`emulator.sh test` поднимает эмулятор **в окне, на GPU хоста** — это вдвое быстрее
headless (50s против 116s) и на гигабайт легче. `--headless` — когда нужно
воспроизвести CI; на голом tty или по ssh скрипт переключается туда сам.

После прогона `test` гасит эмулятор, который сам же и поднял, — в том числе когда
тесты упали или прогон прервали Ctrl-C. Висящие 2.3 ГБ на машине с 8 ГБ — это те
самые гигабайты, которых потом не хватает Gradle. Эмулятор, поднятый до запуска и
в нужном режиме, не трогают: закрывать чужое не дело скрипта. `--keep` оставляет
поднятым в любом случае.

Режим, который просят, всегда и получают: уже поднятый эмулятор в том же режиме
переиспользуется, в другом — гасится и стартует заново (`-no-window` на живом не
переключается). Режим определяется по командной строке процесса, а не по файлу
состояния, поэтому эмулятор, запущенный руками, тоже опознаётся верно.

```bash
scripts/screenshots.sh              # шесть кадров, иконка и feature graphic — одной командой
scripts/screenshots.sh --keep       # не гасить эмулятор после прогона
scripts/screenshots.sh --no-build   # без Gradle, на том, что уже стоит на устройстве
scripts/screenshots.sh --raw        # оставить и кадры без подписей
```

`screenshots.sh` кладёт результат в `store/screenshots/` (плюс `store/icon-512.png` и
`store/feature-graphic.png`). Два прогона подряд дают одинаковые картинки, и это не
случайность: статусбар переводится в demo-режим SystemUI (всегда 12:00, полная батарея,
без иконок уведомлений), библиотека не набивается руками, а восстанавливается из
`store/demo-library.json` **штатным импортом**, анимации на время съёмки выключаются.
Demo-режим и ночную тему скрипт возвращает как было, чем бы прогон ни кончился.

Элементы ищутся по дампу иерархии (`uiautomator dump`), а не по запомненным
координатам: координаты ломаются молча при первом же изменении отступов, и в кадр
попадает не тот экран. Устройство наполняет и иконку рисует `StoreAssetsTest` —
инструментальный тест, который без `-e demoLibrary` / `-e iconOut` пропускается, так что
в обычном прогоне CI он ничего не делает. Запускается он через `am instrument`, а не
через Gradle: `connectedDirectDebugAndroidTest` в конце сносит оба APK и унёс бы
наполненную библиотеку с собой.

Полное описание механик — в `ai-docs/grind-loop.md` (цикл) и `ai-docs/release-and-ci.md`
(`close-task.sh`, ветки, CI). Здесь — порядок действий.

## Быстрый старт

```bash
scripts/grind.sh --once     # одна задача от выбора до мёржа, потом стоп
```

Запускать **из своего терминала**, не из сессии Claude Code: каждая задача — это
отдельный процесс `claude` на переднем плане этого терминала.

Первый прогон лучше делать так: `--once` (одна задача), посмотреть, что получилось,
и только потом отпускать цикл целиком.

---

## Что происходит за один проход

```
выбор задачи  →  автор пишет код  →  PR (без мёржа)  →  ревьюер  →  правки  →  мёрж  →  todo/done/
                 ▲                                        │
                 └──────────── findings ──────────────────┘
```

1. **Выбор и размер — два вызова, две модели.** Оба без инструментов и **вне
   репозитория** (см. ниже, почему это в семь раз дешевле). Сначала Haiku получает
   открытые id и `todo/README.md` и отвечает одним id; потом Sonnet смотрит спеку
   выбранной задачи и отвечает `simple` или `complex` — это слово решает, какая модель
   будет писать код, и Haiku ошибается в нём в дорогую сторону. Повторяется перед каждой
   задачей. Мусорный ответ → откат на порядок бэклога, баги вперёд, размер `simple`.
2. **Автор.** Сессия с фиксированным `--session-id`, читает `todo/{bugs,features}/<id>.md`,
   ветвится от `develop`, пишет код, гоняет `testDirectDebugUnitTest` / `lintDirectDebug` / `detekt`,
   коммитит и заканчивает на `close-task.sh <id> --pr-only` — PR открыт, ничего не
   смёржено.
   Перед этим сессия пишет **описание PR по-русски** в `todo/.grind/<id>.pr.md`
   (что было не так, что изменено и почему именно так, что осталось нетронутым,
   как проверено) и передаёт его через `--body-file`. Строку `Closes …` со
   ссылкой на спеку `close-task.sh` дописывает сам.
3. **Ревью.** Первый раунд — новая сессия с read-only инструментами (`Read,Grep,Glob`,
   без `Bash`): дифф и `--stat` ей отдают прямо в промпте, вместе со спекой и
   инвариантами из `CLAUDE.md`. Отвечает `VERDICT: APPROVE` или
   `VERDICT: REQUEST_CHANGES`; отчёты лежат в `todo/.grind/<id>.review.<n>.md`.
4. **Правки.** Findings отправляются **в ту же** авторскую сессию — она чинит с полным
   контекстом того, как писала код. Следующие раунды продолжают **ту же** сессию
   ревьюера и получают только `git diff <проверенная ревизия>..HEAD`: спека, дифф и
   собственные замечания у него уже есть. Два раунда с `REQUEST_CHANGES` переводят
   автора на Opus.
5. **Закрытие.** После approve — `close-task.sh <id>`: авто-мёрж, ссылка на PR в файл
   задачи, файлы в `todo/done/`, `todo/README.md` помечен ✅, локально `develop` + `pull`.

По умолчанию три раунда ревью, дальше скрипт спрашивает (`--rounds N`, чтобы поднять).

## Флаги `grind.sh`

```bash
scripts/grind.sh                 # спрашивает перед каждой задачей
scripts/grind.sh --yes           # без вопросов, до опустошения бэклога
scripts/grind.sh --once          # ровно одна задача
scripts/grind.sh --task bug-4    # начать с этой, дальше выбирать как обычно
scripts/grind.sh --no-review     # сразу мёрж, без раундов ревью
scripts/grind.sh --rounds 5      # больше раундов, прежде чем сдаться
scripts/grind.sh --mode auto     # останавливаться на рискованных вызовах
scripts/grind.sh --model <name>  # принудительно эта модель для авторских сессий
scripts/grind.sh --model-simple sonnet --model-complex opus --model-review sonnet
scripts/grind.sh --model-pick haiku --model-size sonnet     # ранжирование и размер
scripts/grind.sh --effort-author max --effort-review high   # или --effort сразу всем
scripts/grind.sh --escalate-after 3    # позже отдавать буксующего автора Opus
scripts/grind.sh --no-escalate         # никогда; --model означает то же
scripts/grind.sh --autocompact 150k    # или 'auto' (решает claude), или 'off'
scripts/grind.sh --no-hotkey     # не читать клавиатуру, пока идёт задача
```

## Какая модель что делает

| сессия | модель | почему |
| --- | --- | --- |
| выбор задачи (какой id) | `haiku` | ранжирование списка, который уже в промпте |
| размер задачи (`simple`/`complex`) | `sonnet` | это слово решает, какая модель пишет код |
| автор, задача `simple` | `sonnet` | один-два файла, правка текста или очевидный краевой случай |
| автор, задача `complex` | `opus` | схема БД или миграция, `TrackerRepository`/DAO/синхронизация, новый экран, продуктовое решение, размытая спека |
| ревьюер | `sonnet` **всегда** | чтение диффа по чек-листу; `--model` сюда не действует |

Размер ставит тот же вызов, что выбирает задачу: он отвечает `<id> <simple|complex>`.
Не разобрали ответ, задачу дали через `--task`, вообще нет ответа — берётся
`complex`, то есть Opus: ошибиться в дорогую сторону дешевле, чем отдать Sonnet
миграцию схемы.

Выбранная модель ложится в `todo/.grind/<id>.model`, поэтому `resume` после
лимита продолжает разговор на той же модели, на которой он начинался.

## Сколько думает каждая сессия

`claude --effort`, тоже по работам, и по умолчанию **`high` везде**:

| сессия | флаг | по умолчанию |
| --- | --- | --- |
| автор (реализация) | `--effort-author` | `high` |
| ревьюер | `--effort-review` | `high` |
| выбор задачи и её размер | `--effort-pick` | `low` |

`--effort <level>` ставит все три разом. Уровни: `low`, `medium`, `high`, `xhigh`,
`max`. High у автора и ревьюера — решение, а не лень: автор пишет в код, где сломанный
инвариант стоит стёртой библиотеки или отклонённой сборки, а ревьюер — единственное,
что стоит между неверным диффом и `develop`. Пикеру же думать не над чем: он отвечает
двумя словами, а thinking оплачивается как output — самый дорогой токен из всех.

Неверный уровень отклоняется на старте, а не самим claude: пропущенный дальше, он
роняет по сессии за раз — уже после того, как оплачены модель и промпт, — и цикл читает
это как «сессия кончилась рано» и повторяет пять раз. Сборка claude без `--effort`
определяется один раз по `--help`, флаг тогда не передаётся, о чём печатается
предупреждение.

---

Режим по умолчанию — `bypassPermissions`: разрешений не спрашивают вообще. Это и есть
смысл цикла без присмотра, но помнить стоит: такие сессии сами пушат ветки, открывают
PR и взводят авто-мёрж. `--mode acceptEdits` спрашивает про всё, кроме правок файлов.

## Смотреть, но не печатать

Сессии неинтерактивные (`claude -p`) — иначе после выполненной работы `claude` встаёт
у своего промпта и ждёт, а скрипт над ним висит до Ctrl-C, и ни ревью, ни мёржа не
будет. Поэтому:

- в терминале видно всё — мысли, вызовы инструментов, их результаты, итог по стоимости;
  это рендерит `claude-stream.py`;
- **вводить туда ничего нельзя** — сессия не читает stdin;
- вопросов сессия не задаёт: в промпте ей сказано решать самой и фиксировать допущение.

У каждого события есть время: строки самого скрипта, старт сессии, каждый вызов
инструмента и его результат, конец прогона. У потоковой прозы времени нет — она идёт
по символу. Прогон длится часами, и читают лог потом: чтобы понять, куда ушёл вечер.

Ctrl-C останавливает прогон, но не теряет работу — см. ниже.

## Откуда берётся расход токенов

По транскриптам этого проекта (148 сессий, 5913 ходов): 523M токенов чтения кэша, 26.6M
записи, 3.5M вывода. То есть **примерно половина счёта — это пересылка того, что уже
лежит в контексте**, а треть — то, что туда кладут. Каждый ход отправляет весь разговор
заново, поэтому всё, что вошло рано, умножается на число оставшихся ходов, а сессия,
забившая контекст, умирает недоделанной — и выглядит это как упёршийся лимит.

Что из этого следует и где это зашито:

- **Пикер и сайзер запускаются вне репозитория** — `$TMPDIR/dosmotr-grind-pick`, с
  `--system-prompt`, `--strict-mcp-config` и `--effort low`. `CLAUDE.md` ищется от
  рабочего каталога вверх, так что в scratch-каталоге его нет. На настоящем промпте
  пикера замерено: **33.4k токенов против 4.4k** за ответ из двух слов. Безопасно это
  только для них: у них нет инструментов и они не трогают дерево. `--bare` сделал бы то
  же одним флагом, но не читает OAuth-логин (*Not logged in*) — ему нужен
  `ANTHROPIC_API_KEY`, а это другой счёт.
- **Ревьюеру дифф отдают в промпте**, `Bash` у него нет — только `Read,Grep,Glob`. Сам он
  добывал `git diff origin/develop...HEAD`: самый большой результат инструмента в логах
  репозитория — 289 КБ, это ~70k токенов до конца раунда. Теперь в промпте `--stat` и
  дифф, обрезанный по `REVIEW_DIFF_MAX` (80 КБ), с указанием дочитать файлы через `Read`.
- **Раунды со второго продолжают ту же сессию ревьюера** и получают только
  `git diff <последняя проверенная ревизия>..HEAD`. Спека, дифф и собственные замечания у
  него уже в разговоре; холодный старт стоит ~29k токенов. Id сессии сохраняется только
  после раунда с вердиктом — сессию, которая умерла до того, как возникла, нельзя
  «продолжить» в ошибку.
- **Длинные авторские сессии сжимают сами себя** — `--autocompact`, по умолчанию 100k
  токенов (только автору: раунд ревью — это один ход). По транскриптам проекта сессии
  доходят до 200–300k контекста, а автосжатие сработало ровно один раз на 148 сессий, и то
  вручную. Без него последние ходы длинной задачи перечитывают по четверти миллиона
  токенов каждый.
- **`--exclude-dynamic-system-prompt-sections`** выносит cwd, окружение и **`git status`**
  из системного промпта (это кэшируемый префикс) в первое пользовательское сообщение.
  `git status` меняется с каждым коммитом, поэтому без флага каждая сессия заново
  оплачивает всё, что идёт после него: замерено на смене состояния git — 26.1k токенов
  перезаписи против 21.0k. С `--system-prompt` флаг игнорируется, так что пикеру и
  сайзеру не достаётся.
- **CLAUDE.md разрезан.** Было 775 строк / 46.8 КБ ≈ 11.7k токенов в каждой сессии на
  каждом ходу; стало 155 строк / 9.3 КБ ≈ 2.3k, остальное — в `ai-docs/`, куда сессия
  идёт по конкретному поводу. В ядре осталось то, нарушение чего стоит дорого:
  инварианты, юридические границы, «в develop только через PR».
- **Промпту автора отдельным абзацем сказано беречь контекст**: искать код через
  CodeGraph, а не читать файлы целиком (`LibraryScreen.kt` — 47 КБ, `DetailScreen.kt` —
  53 КБ), гонять сборку в лог и читать только хвост при падении (в логах есть результаты
  gradle на 107 и 98 КБ), `--stat` перед `diff`, скриншот снимать один раз и описывать
  словами — одна сессия прочитала один и тот же PNG семь раз.

## Доделать задачу и остановиться: `f`

Ctrl-C рвёт прогон там, где он стоит: посреди раунда ревью это открытый PR и сессия,
которую придётся поднимать руками. `f` — вежливый вариант: текущая задача доводится до
конца (ревью, мёрж, `close-task.sh`), и цикл выходит вместо того, чтобы взять следующую.

- `f` (и `q`, пока идёт задача) — «останови после этой»;
- `c` — отменить запрос, пока задача ещё не кончилась;
- `touch todo/.grind/stop` — то же самое из другого терминала или по ssh.

Клавиатуру на время задачи слушает фоновый читатель; на каждом вопросе скрипта он её
отдаёт, иначе два читателя на одном tty делят ответ между собой. Отключается флагом
`--no-hotkey`, и сам отключается там, где управляющего терминала нет.

## Лимиты, Ctrl-C, закрытый ноутбук

У каждой задачи фиксированный session id в `todo/.grind/<id>.session`. Прогресс
меряется артефактами, а не словами сессии: фаза 1 закрыта, когда `gh pr list` показывает
открытый PR; фаза 3 — когда появился `todo/done/<id>.md`.

Сессия кончилась, а PR нет — скрипт предлагает:

```
[r]esume  [w]ait 1h then resume  [s]kip  [q]uit
```

`r` продолжает **ту же** переписку со всем контекстом. `s` и `q` печатают команду
`claude --resume <id>` — вернуться можно когда угодно.

Если сессию убил лимит, вопрос не задаётся вовсе: раньше времени сброса продолжать
нечего. Сессия сама говорит, когда лимит снимется — эпохой
(`Claude AI usage limit reached|1754661600`) или словами (`resets 3pm`,
`will reset at 15:00 (UTC)`); `claude-stream.py` разбирает и то и другое в
`todo/.grind/limit` как `<epoch>\t<локальное время>`, а цикл спит ровно до этого момента
плюс две минуты — и в фазе 1, и между раундами ревью. Фиксированные 15 минут были либо
двенадцатью бессмысленными повторами против трёхчасового лимита, либо часом простоя
против двухминутного.

Формулировку пишет не наш код, поэтому есть ограничители: сброс, который уже прошёл, —
минута паузы; дальше шести часов — обрезается до шести; сессия, которая не сказала
ничего, — те самые 15 минут. Всё, что не разбирается как JSON (включая stderr `claude`,
где лимит объявляют не реже, чем в stdout), печатается как есть, а не проглатывается.

---

## Одна задача вручную

Цикл не обязателен. Если задачу сделали руками на `feature/<name>`:

```bash
scripts/close-task.sh feature-11                       # заголовок PR = subject последнего коммита
scripts/close-task.sh bug-3 --title "fix: …"
scripts/close-task.sh feature-11 --no-wait             # взвести авто-мёрж и не ждать
scripts/close-task.sh feature-11 --pr-only             # только открыть PR
scripts/close-task.sh feature-11 --body-file my.md     # описание PR из файла
```

Описание PR — обычный текст на русском: что и зачем. Без `--body-file` в теле
остаётся только ссылка на файл задачи.

Скрипт откажется работать где-либо, кроме ветки `feature/**`, и при грязном дереве.
`--pr-only` — это ровно та половина, которую делает авторская сессия перед ревью;
повторный запуск без флага подхватывает тот же PR и доводит дело до конца.

`todo/` в `.gitignore`, поэтому вся бухгалтерия (ссылка на PR, перенос в `done/`,
галочки в индексе) — локальная: ничего не коммитится и ничего не пушится в `develop`.

---

## Что должно быть включено на GitHub

- **Allow auto-merge** в настройках репозитория — без этого `close-task.sh` оставит PR
  открытым, а не смёржит его другим способом.
- Защита `develop` со всеми семью проверками CI (описана в `CLAUDE.md`). Если PR
  сливается мгновенно — проверить в первую очередь именно её.

---

## Когда что-то пошло не так

| симптом | причина |
| --- | --- |
| PR слился, не дождавшись CI | на `develop` нет защиты ветки / не требуются проверки |
| PR висит, проверок ноль | у head-коммита маркер пропуска CI; `close-task.sh` толкает пустой коммит сам |
| красный чек на ветке после мёржа | `--delete-branch` убрал ветку, `actions/checkout` упал — это бухгалтерия, а не сломанная сборка; вердикт — прогон на `develop` |
| `Input must be provided either through stdin or as a prompt argument` | промпт стоит после `--tools`: флаг вариадический и съедает его. `claude_run` подаёт промпт в stdin именно поэтому |
| `the reviewer produced nothing` / `answered without a VERDICT line` | ревьюер не отработал (лимит, сбой). Это **никогда** не approve: раунд повторяется (под `--yes` — пять раз с паузой 15 минут), не помогло — PR остаётся открытым и несмёрженным |
| цикл предлагает одну и ту же задачу | она в пропущенных на этот прогон; `--task <id>`, чтобы вернуться к ней |
| скрипт «висит» без вывода | ждёт мёржа; ожидание ограничено часом, потом PR остаётся открытым |

Память машины — отдельная тема: эмулятор (~2.5 ГБ) и Gradle (~2.8 ГБ) рядом с браузером
в 8 ГБ не помещаются, см. «Memory budget» в `CLAUDE.md`.
