# Досмотр

Android-приложение для отслеживания просмотра сериалов и фильмов: библиотека
тайтлов, отметки серий по сезонам, статусы, оценки, заметки и статистика
потраченного времени. Метаданные приходят из собственного бэкенда, плюс ручное
добавление для всего, чего в нём нет.

Название — про то, чем приложение занимается: помогает довести начатое до конца.

**Сайт проекта:** <https://simane988.github.io/dosmotr/> — там же
[политика конфиденциальности](https://simane988.github.io/dosmotr/privacy/)
([EN](https://simane988.github.io/dosmotr/privacy/en/)) и способы поддержать автора.
Публикуется GitHub Pages из каталога [`docs/`](docs/).

## Возможности

- **Библиотека** — карточки с постером, прогрессом (`12 / 24`), кнопкой «+1 серия»,
  фильтрами по статусу/типу и поиском по названию.
- **Поиск** — запрос к бэкенду с дебаунсом, тренды недели на пустом запросе,
  добавление в один тап; уже добавленные помечены галочкой.
- **Ручное добавление** — название, тип, серии по сезонам строкой `12, 10, 8`,
  длительность и год. Работает без сети и без настроенного бэкенда.
- **Экран тайтла** — сезоны сворачиваются, чекбокс на серию, «весь сезон»,
  «отметить всё до этой серии» (догнать прогресс), статус, оценка 1–10, заметки,
  обновление из бэкенда (подтягивает новые вышедшие серии, не трогая отметки).
- **Статистика** — суммарное время, серии, фильмы, разбивка по статусам.
- **Экспорт/импорт JSON** — меню «⋮» в шапке библиотеки. Через Storage Access
  Framework, поэтому разрешений на файлы не требуется.
- Статус ведётся сам: последняя серия → «Просмотрено», снял отметку → «Смотрю».
- Всё хранится локально в Room, сеть нужна только для поиска и обновления.

## Стек

Kotlin · Jetpack Compose (Material 3) · Room · Hilt · Retrofit + kotlinx.serialization ·
Coil · Navigation Compose. minSdk 26, compileSdk 35.

## Сборка

1. Установи JDK 17 и Android SDK (проще всего — Android Studio).
2. Подними бэкенд — см. репозиторий `dosmotr-backend` — и возьми оттуда адрес и токен.
3. Скопируй `local.properties.example` в `local.properties` и заполни:

   ```properties
   sdk.dir=/путь/к/Android/Sdk
   backend.url=https://dosmotr.g3ck0-tech.ru
   backend.token=твой_токен
   ```

   Ключи `donate.*` (см. `local.properties.example`) заполнять не нужно: без них
   собирается флейвор `direct` без блока донатов — см. «Сборки» ниже.

4. Собери:

   ```bash
   ./gradlew assembleDirectDebug      # apk в app/build/outputs/apk/direct/debug/
   ./gradlew installDirectDebug       # на подключённое устройство
   ./gradlew test                     # юнит-тесты
   ./gradlew installDirectProfileable # сборка для замеров производительности
   ```

   Wrapper-jar в репозитории нет. Если `./gradlew` не запускается, один раз выполни
   `gradle wrapper --gradle-version 8.9` или открой проект в Android Studio —
   она сгенерирует его сама.

Без `backend.url` приложение собирается и работает, но экран поиска показывает
подсказку и остаётся только ручное добавление. `backend.url` без `backend.token`
роняет сборку: иначе каждый запрос молча получал бы 403.

Приложение знает только свой бэкенд и его пути `/v1/*` и `/img/*`. Откуда бэкенд
берёт данные — его дело; источник можно сменить на сервере, не выпуская новую сборку.
Язык и фильтрация контента прибиты там же, потому что это свойства источника,
а не клиента.

## Сборки

Флейворов два, `applicationId` и ключ подписи у них общие — это одно приложение,
а не два, и APK с GitHub Releases обновляется магазинной сборкой без потери библиотеки.

| Флейвор  | Куда                          | Донаты |
|----------|-------------------------------|--------|
| `direct` | GitHub Releases, IzzyOnDroid  | есть, если заполнены `donate.*` |
| `store`  | RuStore, Google Play          | нет — ни блока, ни адреса в APK |

Разница только в этом, и она не вкусовая: часть 7 статьи 14 259-ФЗ запрещает
распространение информации о приёме цифровой валюты, а внешняя кнопка перевода
читается Google Play как обход их биллинга. Поэтому в `store` не «спрятан» блок —
там пустые строки вместо адресов, то есть адреса нет и в самом APK.

Каждая задача Gradle называется с флейвором: `installDirectDebug`,
`testStoreDebugUnitTest`, `connectedDirectDebugAndroidTest`. Просто `installDebug`
больше нет.

## Структура

```
app/src/main/java/com/g3ck0/seriestracker/
├── data/
│   ├── local/        Room: TitleEntity, EpisodeEntity, TrackerDao, конвертеры
│   ├── remote/       CatalogApi, DTO, CatalogImage
│   └── repository/   TrackerRepository — единственный источник правды для UI
├── di/AppModule.kt   Room, OkHttp (токен бэкенда интерцептором), Retrofit
└── ui/
    ├── library/      список + фильтры
    ├── search/       поиск и ручное добавление
    ├── detail/       сезоны, серии, статус, оценка, заметки
    ├── stats/        сводка
    └── common/       постеры, русские склонения, форматирование времени
```

Рядом с кодом лежит `docs/` — сайт проекта на GitHub Pages: главная, политика
конфиденциальности на двух языках, страница «Поддержать автора» и заготовка лендинга
для сирот TV Time. Реквизиты переводов на сайте задаются в `docs/_config.yml`;
пустое значение — рабочее состояние, такой способ просто не показывается. В APK
магазинных сборок реквизитов нет вообще (`store` компилирует их пустыми строками),
поэтому оттуда ведёт только ссылка «Сайт проекта» в «О приложении».

### Модель данных

`TitleEntity.id` — строка вида `tv_1399` / `movie_550` / `local_<uuid>`, поэтому
один и тот же тайтл нельзя добавить дважды, а ручные записи не конфликтуют
с каталожными.
Фильмы не заводят строк в `episodes` — у них флаг `movieWatched`. Сериалы считают
прогресс подзапросами `COUNT(*)` в `TrackerDao.observeLibrary()`.

Серии вставляются с `OnConflictStrategy.IGNORE`, так что обновление из бэкенда
добавляет новые вышедшие эпизоды и не сбрасывает отметки о просмотре.
Нулевой сезон (спецвыпуски) пропускается — иначе он ломает проценты.

## Тесты

330 тестов: 139 на JVM и 191 на устройстве. Прогон:

```bash
./gradlew testDirectDebugUnitTest        # секунды, без устройства
./gradlew connectedDirectDebugAndroidTest # нужен телефон или эмулятор
```

**JVM (`app/src/test`)** — логика без Android. Опираются на рукописные фейки
(`fake/FakeTrackerDao`, `fake/FakeCatalogApi`), не на моки:

| Файл | Что закрывает |
|---|---|
| `TrackerRepositoryTest` | статусы, watchUpTo, markNext, сезон 0, слияние при refresh, статистика |
| `LibraryViewModelTest` | фильтры и их комбинации, сообщения, удаление |
| `SearchViewModelTest` | дебаунс (одна сеть на серию нажатий), тренды, ошибки, добавление |
| `DetailViewModelTest` | группировка по сезонам, «дальше», автозагрузка серий, отсутствие сети для ручных записей |
| `StatsViewModelTest`, `BackupTest`, `LabelsTest`, `ProgressTest` | агрегаты, JSON round-trip, склонения, прогресс |

**На устройстве (`app/src/androidTest`)**:

| Файл | Что закрывает |
|---|---|
| `TrackerDaoTest` | реальный SQL: каскады, `IGNORE` vs `Upsert`, порядок библиотеки, статистика |
| `BackupRepositoryTest` | merge/replace, объединение отметок, битые и «будущие» файлы |
| `LibraryContentTest`, `SearchContentTest`, `DetailContentTest`, `StatsContentTest` | экраны |
| `AboutDialogTest` | блок донатов есть ровно там, где разрешён флейвором; в `store` нет и адресов |
| `DarkThemeTest` | те же экраны в тёмной схеме |

Тесты рисуют контент через `setThemedContent` (`ui/ThemedContent.kt`), а не голым
`setContent`: иначе Compose подставляет свою тему по умолчанию — светлую, которой в
приложении нет. `dynamicColor` в тестах выключен, иначе цвета зависели бы от обоев
устройства. Контраст не проверяется: семантика Compose не несёт цвета, поэтому
выцветшая палитра прошла бы тест — это остаётся на глаз или на скриншот-тесты.

### Как это переживёт редизайн

Каждый экран разделён надвое: `XxxScreen` берёт данные из ViewModel, `XxxContent`
рисует переданное состояние и ничего не знает про Hilt. UI-тесты работают с
`XxxContent` напрямую, поэтому им не нужны ни граф зависимостей, ни база.

Элементы адресуются тегами (`LibraryTags`, `SearchTags`, `DetailTags`, `StatsTags`,
`ManualAddTags`), а не текстом и не позицией. Меняя вёрстку, сохраняй теги — тесты
переживут перестановку и переименование. Тесты на видимый текст оставлены только
там, где сам текст и есть контракт («осталось 7 серий», «6 ч 4 мин»).

## Производительность

**По debug-сборке нельзя судить о плавности.** Compose в ней работает без оптимизаций,
и списки заметно дёргаются. Замеры на Pixel 8a, экран сериала с 60 раскрытыми сериями,
`adb shell dumpsys gfxinfo <пакет>`:

| Сборка | Janky frames | Медиана кадра | 90-й перцентиль |
|---|---|---|---|
| `debug` | 78 % | 97 мс | 150 мс |
| `profileable` | 2.3 % | 7 мс | 11 мс |

Для любых измерений используй вариант `profileable` (`debuggable=false`, R8 выключен
намеренно — он тут не влияет на кадры, зато требует памяти):

```bash
./gradlew installProfileable
adb shell dumpsys gfxinfo com.g3ck0.seriestracker.profileable reset
# поскроллить
adb shell dumpsys gfxinfo com.g3ck0.seriestracker.profileable | grep -E "Janky|percentile"
```

Сборка настроена под машину с 8 ГБ ОЗУ (`gradle.properties`): Gradle 1536 МБ,
Kotlin-демон 1280 МБ, `org.gradle.parallel=false`. Без этих лимитов R8 и два демона
вместе выбивают OOM-killer.

## Бэкап в JSON

Меню «⋮» в шапке библиотеки → «Экспорт в JSON» / «Импорт из JSON».
Файл предлагается как `dosmotr-ГГГГ-ММ-ДД.json`.

Формат (`data/backup/BackupModels.kt`), серии вложены в тайтл. Ключ `tmdb_id` сохраняет
историческое имя, чтобы старые бэкапы продолжали импортироваться; в коде это `catalogId`:

```json
{
  "version": 1,
  "exported_at": "2026-07-27T13:00:00Z",
  "app": "dosmotr",
  "titles": [
    {
      "id": "tv_1399",
      "tmdb_id": 1399,
      "type": "TV",
      "name": "Игра престолов",
      "year": "2011",
      "status": "WATCHING",
      "rating": 9,
      "runtime_minutes": 60,
      "notes": "смотрю с женой",
      "episodes": [
        { "season": 1, "episode": 1, "name": "Зима близко",
          "watched": true, "watched_at": 1700000100000 }
      ]
    }
  ]
}
```

Два режима импорта:

- **Объединить** — библиотека остаётся на месте. Недостающие тайтлы добавляются,
  у совпадающих `watched` складывается по ИЛИ (просмотренное не снимается),
  `watched_at` берётся более ранний. Твои статус, оценка и заметки не перетираются —
  из файла подтягивается только то, что локально пусто.
- **Заменить** — библиотека стирается и восстанавливается из файла один в один.

Импорт идёт целиком в одной транзакции Room: при ошибке разбора не применяется
ничего. Неизвестные значения `type`/`status` в правленом руками файле не роняют
импорт, а откатываются к `TV`/`WATCHING`; тайтлы без `id` или `name` пропускаются
и попадают в счётчик «пропущено».
